# Migrating from rclgo v0.6.0

This page lists what changes for programs using rclgo when they move from `jazzy` before #55–#61 (v0.6.0 and the
commits after it) to the code with all of #55–#61. The API differences come from a diff of the exported declarations.
Why the concurrency behaviour changed is explained in [concurrency.md](concurrency.md).

Most programs need two things: **regenerate your message bindings** with the new `rclgo-gen`, and **check your
parameter files** against your declarations. The rest is new API and behaviour that now matches rclcpp.

## Must do

### Regenerate generated message bindings (from #57)
- Bindings generated by an older `rclgo-gen` don't compile against this rclgo. The Go-to-C conversion helpers in
  `pkg/rclgo/primitives` were renamed:
  - `X__Sequence_to_C` → `X__Sequence_into_C`;
  - `X__Array_to_C` → `X__Array_into_C`;
  - `StringAsCStruct` → `StringIntoC`;
  - `U16StringAsCStruct` → `U16StringIntoC`.
- This is deliberate. The new runtime frees the C memory a conversion replaces, and old bindings would have freed
  uninitialised memory without any compile error.
- Regenerate with `rclgo-gen generate …` from this release. Bindings from #56's generator also need regenerating:
  from #56, Spin services subscriptions created with a nil callback correctly, and older generated wrappers called
  that nil callback.

### Parameter values must fit their declarations (from #56)
- A value from a parameter file, `-p` or `RCL_PARAM_*` that is outside the declared range, not in the allowed
  values, or of an incompatible type now makes `Declare`/`DeclareIfMissing` return an error naming the parameter,
  e.g. `parameter "x": override 131072 rejected: above max`. Before, it was accepted silently. An integer still
  widens to a double where a double is declared.
- rclgo doesn't exit; if your program exits on a `Declare` error (most do), it now stops at startup. Check your
  parameter files.
- From #60, `Declare` also validates the **default** you pass against its own descriptor, as rclcpp does. A
  "must be set" sentinel default outside the range is now an error. Load the file first, or drop the range.
- From #60, a declaration that fails leaves the parameter **undeclared** (before, it could still be read and set).

### Small signature changes
| Change | PR | Migration |
|---|---|---|
| `params.Manager.Undeclare(name) bool` → `error` | #60 | `if err := m.Undeclare(n); err != nil {…}`; it now also refuses read-only parameters |
| `rclgo.Clock` and `rclgo.Publisher` are no longer comparable | #56 | compare pointers |
| `gogen.ROS2Field.IsSingleComplex` removed (unused) | #61 | none |

## Behaviour that changed (no code change needed, but know it)

| Area | Before | Now | PR |
|---|---|---|---|
| Entities created after `Spin` starts | never serviced | serviced (subscriptions, timers, services, clients, actions) | #56 |
| Nil-callback subscriptions/timers | Spin called the nil callback | left to their owner to poll | #56 |
| Two Spins on one entity | both raced for it | the first keeps it; a later one warns and skips it | #56 |
| `Close` while Spin runs, or from another goroutine | use-after-free | safe; the rcl handle is freed when no wait set uses it; later calls return `rclgo.ErrClosed` | #56–#58 |
| Periodic timers | period grew by the wake-up latency | exact (`rcl_timer_call`) | #56 |
| Timers under `use_sim_time` | followed the system clock | follow `/clock` (ROS time override) | #57 |
| Nil or wrong-type message to `Publish`, `TakeMessage`, `Send`, `SendResponse`, feedback, action results | panic, possibly in an rclgo goroutine | returns `rclgo.ErrInvalidMessage` | #58 |
| Action handler returning `nil, err` in a generated (type-safe) server | crashed the process | treated as "no result"; no crash | #58 |
| `WatchGoal` for an ABORTED/CANCELED/UNKNOWN goal | nil error | the result plus `*rclgo.GoalFailedError{Status}` | #57 |
| Action-client feedback/status handlers | one goroutine per message (reordered) | in order, one queue per handler; a panicking handler is logged | #57 |
| A panicking logging output handler | reached the logging call | recovered and logged | #58 |
| Bounded sequences longer than their bound | outcome depended on the RMW | refused before sending (`types.ErrBoundExceeded`); bounded strings unchecked, as in rclcpp | #58 |
| `ros2 param` against an rclgo node | didn't work (two services missing) | works; all six services as rclcpp | #57 |
| Parameter-file sections | first match only, plain node name | every matching section, fully qualified name, rclcpp wildcards; `/name` only in the root namespace | #60 |
| Nested YAML maps in parameter files | failed to load | flattened to dotted names | #60 |
| YAML values | own rules | as rcl: YAML 1.1 booleans, an empty list fits any array type, mixed int/float lists rejected | #60 |
| Post-set callbacks | map order | registration order | #60 |
| QoS | durations dropped seconds; negative depth wrapped; zero `ActionServerOptions` discarded results | `{sec,nsec}` both ways; negative durations are infinite; profiles validated; zero options take defaults | #56, #57, #60 |
| Generated unqualified field types (`Header`, `Empty`) | `std_msgs` | the message's own package first, as rosidl | #59 |
| Generated defaults | `True`, `010` emitted as is | as rosidl reads them; inf/nan rejected | #57 |

## New API

- `rclgo.ErrClosed`, `rclgo.ErrInvalidMessage`, `rclgo.GoalFailedError`.
- `Clock.SetROSTimeOverride`, `Clock.EnableROSTimeOverride`, `Clock.DisableROSTimeOverride`.
- `params.Manager.AddPostSetCallback`; `params.ErrNoMatchingSection`, returned when a file has no section for the
  node (callers may ignore it).
- `qos.CheckCompatible` (rmw's own verdict) with `qos.Compatibility` (`CompatibilityOK/Warning/Error`);
  `qos.DurationInfinite`, `qos.DurationToRMW`, `qos.DurationFromRMW`.
- `rostime.ErrTimeJumpedBack`.
- `types.BoundsChecker`, `types.CheckBounds`, `types.ErrBoundExceeded` (+ helpers); generated messages get
  `CheckBounds()`.

## Known pitfalls (unchanged, now documented)

- `params.NewManager` doesn't apply `-p` command-line overrides; call `params.ApplyOverrides` too.
- `Get{Publishers,Subscriptions}InfoByTopic(topic, mangle)` takes the inverse of rcl's `no_mangle`: pass `true` for
  ROS topic names.
- `Node.Spin` doesn't service timers, because timers belong to the Context. Use `Context.Spin`.
- The default service QoS is KEEP_LAST(10), as in rclcpp: a burst of more than 10 requests drops some silently.

## Still open after this release

- rclgo#54: generated typed subscriptions call the user callback with `*SubscriptionTakeFailed` and an empty
  message when `rcl_take` finds nothing; rclcpp/rclpy skip the callback.
- rclgo#19, #20: generator and parameter-YAML corner cases (partly fixed).
- Features not yet implemented: lifecycle nodes, QoS events, executors and callback groups, `WaitForService`
  (rclgo #4–#11).
